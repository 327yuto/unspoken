# UNSPOKEN

スマホ1台を回して遊ぶ、合コン・飲み会向けのパーティゲーム Web アプリ。UI は全て日本語、モバイル縦画面前提（コンテンツ幅は最大 440px）。

## 構成

[index.html](index.html) の1ファイル完結。ビルド工程・パッケージマネージャ・バックエンドは無い。ブラウザで直接開けば動く。

- React 18 / ReactDOM / babel-standalone を CDN から読み込み（バージョン固定）
- JSX は `<script type="text/babel">` 内にそのまま記述
- スタイルは基本インライン style。`@keyframes` と `input` の共通スタイルのみ `<head>` の `<style>` に置く
- 状態は React state のみ。保存・通信・永続化は一切しない（リロードで全消去）

**この単一ファイル構成は意図的なもの**。分割やビルド導入は指示があるまで行わない。

## 画面の流れ

`App` がモード選択を持ち、2つのフローに分岐する。

**MATCH（`SeatFlow`）** — 2択質問の回答一致度で男女をペアにする
`rules`（ルール説明）→ `count`（人数）→ `pickQ`（質問選択・カスタム追加）→ `questions`（内容確認）→ `assign`（番号割り当て）→ `callup` → `answering`（1人ずつ回答）→ `aggregate`（全体集計）→ `pairs`（ペア発表）

**SECRET（`SecretFlow`）** — 質問者側の番号に対して回答者が匿名投票する
`rules` → `count` → `role`（どちらが質問するか）→ `assign`（回答チームが質問チームに番号をつける）→ `toAsker`（質問チームへ端末を渡す）→ `question`（質問設定）→ `shownum` → `answering` → `handoff`（次の回答者へ渡す）→ `result`

各フローは巨大な1コンポーネント内で `if (step === "...") return (...)` を並べる形。ステップを追加するときはこの並びに合わせる。

`App` は `started`（回答が始まったか）を持ち、各フローが `onActive(true/false)` で通知する。ロゴタップでトップに戻る際、消えるデータがあるときだけ確認する判定に使う。画面内のボタンは意図が明確なので確認しない。

## ロジックの要点

- `buildPairs()`: 男女の全組み合わせで一致数を採点し、スコア最大のペアを貪欲に確定していく。同点候補は `Math.random()` で選ぶため**結果は毎回変わりうる**
- 質問ごとの `matchMode` は `"same"`（同じ回答でペア）か `"opposite"`（違う回答でペア）
- `PRESET_QUESTIONS` / `SECRET_TEMPLATES` が質問のプリセット。文言はそのまま画面に出るので短く保つ
- `QUESTION_SETS` は MATCH の質問セット（3問まとめて選べる）。**中身は各質問の `set` タグから導出する**。インデックスで指す形に戻すと、質問を並べ替えたり途中に挿入したときに黙って別の質問を指すため
- `COLORS_M` / `COLORS_F` が男女の識別色。人数がリストより多い場合は剰余で循環する

## SECRET モードの前提

「誰が何番か」を質問チームに知られると匿名性が崩れる設計。次の4つは**ゲームの成立条件そのもの**なので、省略・簡略化しない。

- `assign` は回答チーム専用画面。`asker` を見て回答チーム側だけを表示する
- `toAsker` / `handoff` / `shownum` の受け渡しと警告表示
- 回答直後に選択肢を確認カードへ差し替える（**両モード共通**）。選んだものを強調したまま残すと、覗き見に対して最も情報が漏れる
- 結果を開く前に主催者へ端末を渡す画面（MATCH は `aggregate`、SECRET は `result`）。ここで秘匿フェーズの終わりを明示する

MATCH の番号は逆に**公開前提**。`callup` で読み上げられ結果も番号で出るので、隠す必要はない。2モードで番号の扱いが正反対な点に注意。
